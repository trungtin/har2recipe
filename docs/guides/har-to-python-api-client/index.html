How to turn a HAR file into a Python API client that replays without a browser

Short answer: a HAR file is a JSON log of every request the page made, so the site's hidden API is already in it. Load it in Python, keep the entries whose response is JSON, and find the one that returns your data. Copy its method, URL, the few headers it really needs and its body, then rebuild the call with requests. Put the parts that change (search word, page, cursor) into function arguments, and you have a client that runs with no browser. One endpoint takes about 20–40 minutes by hand. It won't work if the site signs every request or sits behind heavy bot protection; step 4 shows how to tell.

You need Python 3.9+ and pip install requests. Only use this on data you're allowed to read, and respect the site's terms and rate limits.

The manual method, step by step

1. Record a small HAR

  • Chrome or Edge: open DevTools > Network, tick Preserve log, pick the Fetch/XHR filter, then do the one action you want data from (a search, the next page). Click the download arrow to export the HAR.
  • Firefox: DevTools > Network, do the action, then right-click any request > Save All As HAR.
  • Safari: Web Inspector > Network, do the action, then Export.

Keep it small: one page, one action. A 40 MB HAR full of images and analytics hides the one call you need.

Recent Chrome versions export a sanitized HAR by default, without cookies or Authorization headers. That is safer to keep around. If the call needs a login, you'll pass your token from an environment variable in step 5, so you don't need the sensitive export.

2. List the data calls

A HAR is plain JSON: log.entries[], each with a request and a response. This prints only the calls that returned JSON:

import json

har = json.load(open('site.har', encoding='utf-8'))
for i, e in enumerate(har['log']['entries']):
    res = e['response']
    if 'json' in res['content'].get('mimeType', ''):
        size = res['content'].get('size', 0)
        print(i, e['request']['method'], res['status'], size, e['request']['url'][:110])

Look for URLs with /api/, graphql, search or .json. The biggest response is usually the one with your list. Open it to confirm:

e = har['log']['entries'][17]          # the index you picked
print(json.dumps(e['request'], indent=1)[:2000])
print(e['response']['content'].get('text', '')[:1000])

If content.encoding is base64, decode the text before reading it.

3. Replay it from Python

Rebuild the request from the entry. Drop HTTP/2 pseudo-headers (they start with :), cookies and headers that requests sets itself:

import requests

SKIP = {'cookie', 'content-length', 'host', 'accept-encoding', 'connection'}

def replay(entry):
    req = entry['request']
    headers = {h['name']: h['value'] for h in req['headers']
               if not h['name'].startswith(':') and h['name'].lower() not in SKIP}
    body = (req.get('postData') or {}).get('text')
    r = requests.request(req['method'], req['url'], headers=headers, data=body, timeout=30)
    r.raise_for_status()
    return r.json()

data = replay(e)
print(type(data), list(data)[:10] if isinstance(data, dict) else len(data))

Same JSON as in the browser? The hard part is done. A 401 or 403 means a header is missing. Add back one at a time: authorization, x-api-key, a CSRF token, referer/origin, then the cookie.

4. Check that it works without the browser

Run it again in ten minutes and again tomorrow. Each kind of failure has its own fix:

  • A token that expires (it works now, fails in an hour): find the request in the HAR that returns the token, call it first, and pass the token on.
  • A signed parameter (a hash that is different on every request, often signature, sign or _s): page JavaScript computes it, so plain HTTP usually can't reproduce it.
  • Bot protection (a 403 with an HTML challenge page instead of JSON): you need a real browser such as Playwright, or the site's official API.

5. Wrap it in a small client

Now replace the copied URL with a function. Arguments become query parameters, secrets come from the environment, and the function returns only the fields you need:

import os
import requests

class ExampleClient:
    BASE = 'https://api.example.com/v1'

    def __init__(self, token=None):
        self.s = requests.Session()
        self.s.headers.update({
            'accept': 'application/json',
            'user-agent': 'Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_7)',
        })
        token = token or os.environ.get('EXAMPLE_TOKEN')
        if token:
            self.s.headers['authorization'] = 'Bearer ' + token

    def search(self, query, limit=20):
        r = self.s.get(self.BASE + '/search', params={'q': query, 'limit': limit}, timeout=30)
        r.raise_for_status()
        items = r.json()['data']['results']
        return [{'title': x['name'], 'price': x['price']['amount']} for x in items]

print(ExampleClient().search('shoes', limit=5))

For paging, read the cursor or next field from each response and loop until it's empty.

6. Notice the day it breaks

Sites move endpoints and rename fields without telling anyone, and a client that returns [] looks the same as one that works. Add a check and run it on a schedule:

items = ExampleClient().search('shoes')
assert len(items) >= 10 and all(x['title'] for x in items), 'stale: capture a new HAR'

Treat a HAR like a password file

  • Unless the export is sanitized, it holds your cookies, bearer tokens and form bodies, including login forms. Never paste one into a chat or an issue.
  • Keep tokens in environment variables, not in the client file.
  • Review any generated code before you run it.

Where doing it by hand stops working

Doing this once is fine. But every new site means another 20–40 minutes of reading JSON, chasing a missing header and writing the paging loop. Clients built by hand also break silently, and nothing tells you until someone sees an empty table.

Quick answers

Can I convert a HAR file to Python without writing code?

For a single request, yes: copy it as cURL and paste it into curlconverter. For a reusable client with parameters and paging, you write the wrapper yourself (step 5) or have a tool generate it.

Why does my replay get 403 when the browser works?

Usually a missing header (a token, a CSRF value, origin) or an expired cookie. If the 403 body is an HTML challenge page, it's bot protection, and plain HTTP won't get through.

Is a HAR file safe to share?

Not unless it's sanitized. It can hold session cookies and tokens that let someone act as you.

Does this work for GraphQL?

Yes. The call is a POST to one URL with the query in the body. Keep the body as is, and turn the variables into function arguments.
